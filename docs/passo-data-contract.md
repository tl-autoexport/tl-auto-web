# Passo: этап 2 — контракт данных каталога

Статус: согласование перед dry-run.

Цель: добавить объявления Passo в общую витрину TL Auto, сохранив Encar как независимый источник автомобилей.

## Источники

| Источник | Значение `primary_source` | Типы |
|---|---|---|
| Passo Bike | `passo_bike` | `motorcycle`, `scooter` |
| Passo Boat | `passo_boat` | `jetski` после подтверждения по справочнику типа |

Правило: `source_id` — идентификатор `goods_id` Passo. Уникальность сохраняется по паре `primary_source + source_id`.

## Общие поля карточки

| Поле TL Auto | Назначение |
|---|---|
| `vehicle_type` | Нормализованный тип техники |
| `primary_source` | Источник объявления |
| `source_id` | ID объявления Passo |
| `source_url` | Прямая ссылка на карточку Passo |
| `published_at` | Дата публикации, если есть в карточке/списке |
| `source_updated_at` | Дата последнего обновления объявления |
| `brand` | Марка/производитель |
| `model` | Модель |
| `badge` / `badge_detail` | Комплектация или модификация |
| `year` | Год выпуска |
| `mileage_km` | Пробег, если указан |
| `price_krw` | Цена в исходной валюте, если источник её отдаёт |
| `seller_region` | Регион продавца |
| `vehicle_specs` | Категорийные характеристики в JSONB |

## Категорийные характеристики

### Мотоциклы и скутеры

В `vehicle_specs` сохраняем только необходимые для витрины значения:

- тип: мотоцикл / скутер / ATV, если источник различает их;
- объём двигателя;
- мощность, если есть;
- тип топлива;
- коробка передач;
- привод/тип привода, если есть;
- цвет;
- страна производства;
- состояние и дополнительные признаки из карточки.

### Гидроциклы

- тип техники;
- производитель и модель;
- год;
- моточасы или пробег, если есть;
- объём двигателя;
- мощность;
- количество мест;
- цвет;
- регион;
- состояние и комплектность.

Всё, что не подтверждается структурированным полем источника, не заполняем догадками.

## Фото

Главное изображение — URL с суффиксом `_b_1.img`, если оно присутствует. Резервное главное изображение — `_s_1.img`.

Дополнительные изображения сохраняются в `car_media` с:

- `source = passo_bike` или `passo_boat`;
- `media_type = image`;
- `legal_mode = external_url`;
- `is_primary = true` только у одного изображения;
- последовательным `sort_order`.

Фото не скачиваем в Supabase Storage на первом этапе: это увеличит расход базы. Возможность локального кэширования оцениваем после проверки стабильности URL и условий источника.

## Свежесть

Для витрины принимаем только объявления с датой публикации/обновления не старше 30 дней. Записи без даты не импортируем автоматически, а выводим отдельной строкой dry-run в отчёте.

При следующем обновлении:

- объявления, исчезнувшие из свежего списка, получают `is_available = false`;
- связанные медиа и опции удаляются по действующей политике оптимизации;
- Encar-объявления не затрагиваются запросами Passo.

## Расчёт

На этапе Passo-каталога расчёт «под ключ» не включаем автоматически. Сначала собираем и показываем каталог, характеристики и цену источника. Правила доставки, пошлины и комиссий для мототехники и гидроциклов согласуются отдельно.

## Checkpoint этапа 2

Контракт совместим с уже добавленными в TL Auto `vehicle_type` и `vehicle_specs`. Для записи в базу потребуется только расширить типы репозитория/витрины и добавить отдельный Passo-адаптер; Encar-импорт менять не нужно.

Следующий шаг после согласования: этап 3 — read-only dry-run с полной пагинацией, фильтром 30 дней, проверкой карточек и доступности главного фото. Dry-run не будет выполнять INSERT/UPDATE/DELETE.

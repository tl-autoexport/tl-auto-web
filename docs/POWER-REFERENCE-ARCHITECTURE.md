# Справочник мощности и допуск к расчёту

## Цель

Сделать расчёт утилизационного сбора воспроизводимым: каждая рассчитанная
мощность должна быть привязана к конкретному доказательству, правилу
применения и версии нормативной таблицы. Список моделей, полученный от
заказчика, полезен для поиска и приоритизации, но не является сам по себе
основанием для публикации цены.

## Главный принцип

В цену попадают только **утверждённые** характеристики. Импортированные
строки Excel, значения пиковых мощностей и догадки по названию комплектации
остаются в отдельном контуре и никогда не меняют цену автоматически.

```text
сырой источник -> кандидат на сопоставление -> доказательство -> утверждённая спецификация -> расчёт
                  (не влияет на цену)          (не влияет на цену)       (может влиять на цену)
```

## Термины

| Термин | Смысл |
| --- | --- |
| Исходная строка | Неизменённая запись из Excel, HAR, спецификации производителя или СБКТС. |
| Доказательство | Документированное значение мощности с URL/файлом, страницей, датой и типом мощности. |
| Спецификация | Нормализованная версия характеристик для конкретной модели, поколения, силовой установки и периода выпуска. |
| Правило сопоставления | Набор условий, по которым объявление может получить утверждённую спецификацию. |
| Расчётная мощность | Значение, которое требует нормативный режим: не обязательно поле `power_hp` в объявлении. |

## Источники и приоритет

1. СБКТС / ОТТС / ЭПТС конкретного автомобиля или официальная карточка типа ТС.
2. Официальная техническая документация производителя для точной версии.
3. Проверенный VIN-декодер с первичным источником.
4. Экспертный список заказчика — только как кандидат на проверку.
5. Данные объявления Encar — только для первичного сопоставления.

Значения `peak`, `maximum` и диапазоны вида `60–90 кВт` не допускаются к
расчёту, пока не найдено подтверждённое 30-минутное значение либо иной
нормативно применимый параметр.

## Модель расчётной мощности

Расчёт хранит исходные величины без округления:

| Силовая установка | Расчётная мощность для утильсбора |
| --- | --- |
| Бензин / дизель | Подтверждённая мощность ДВС в кВт. Л.с. — представление для каталога. |
| Электромобиль | Максимальная 30-минутная мощность электродвигателя(ей), кВт. |
| Последовательный гибрид | Максимальная 30-минутная мощность электродвигателя(ей), кВт. |
| Параллельный гибрид | Подтверждённая мощность ДВС в кВт + максимальная 30-минутная электрическая мощность в кВт. |

Округление до целых, десятых или «в большую сторону» для выбора диапазона не
допускается. Конвертация л.с. <-> кВт допускается лишь как отображение, если
нет первичного значения в кВт; рядом должна храниться формула и источник.

## Разделение данных в базе

Будут введены четыре независимых слоя.

### 1. Наборы импортов (`vehicle_power_source_batches`)

Хранят источник целиком: название, тип, контрольную сумму файла, дату импорта,
автора, ссылку/путь и статус. Повторный импорт того же файла не создаёт
необъяснимых изменений.

### 2. Сырые записи (`vehicle_power_source_rows`)

Хранят значение каждой строки без потерь: номер листа и строки, исходный JSON,
текст модели, VIN, указанные мощности, примечания и предупреждения парсера.
Они неизменяемы и не участвуют в расчёте.

### 3. Доказательства (`vehicle_power_evidence`)

Хранят подтверждённые факты: тип источника, URL/документ, страницу, дату,
силовую установку, мощность ДВС, 30-минутную электромощность, единицы и
применимость по модели/году. Одно доказательство может поддерживать несколько
утверждённых спецификаций.

### 4. Утверждённые спецификации и правила (`vehicle_power_specs`,
`vehicle_power_spec_matches`)

`vehicle_power_specs` содержит версию юридически значимых параметров и статус
`draft | approved | retired`. `vehicle_power_spec_matches` описывает, к каким
марке, модели, поколению, топливу, объёму, году и варианту относится
спецификация. Только `approved`-спецификация с доказательством высокой
надёжности может участвовать в цене.

Каждое применение записывается в `cars.vehicle_specs.calculation_power` с
идентификатором спецификации и её версией. Это позволяет повторить прошлый
расчёт даже после обновления справочника.

## Правила сопоставления объявления

1. Сначала точный VIN / код модели / код двигателя.
2. Затем точное совпадение марки, модели, поколения, топлива, объёма и периода
   выпуска.
3. Название комплектации само по себе не может быть единственным критерием,
   если оно не уникально.
4. Если совпало более одной спецификации либо не совпало ни одной — цена не
   пересчитывается автоматически; объявление получает понятный статус
   `calculation_power_review_required`.
5. Для N1, пикапов и иных не-M1 категорий действует отдельный расчётный путь.
   Они не используют таблицу легковых M1.

## Контроль публикации

Перед публикацией цена должна пройти все проверки:

- есть статус `approved`;
- есть идентификатор доказательства;
- единицы и тип мощности согласованы с типом силовой установки;
- категория ТС определена;
- расчётная мощность попадает в подтверждённую нормативную таблицу;
- дата первой регистрации известна достаточно для возрастной категории;
- калькулятор записал версию норматива и версии спецификации.

При нарушении любого условия карточка остаётся доступна, но расчёт показывает
«Нужна проверка характеристик», а не выдуманную сумму.

## Порядок реализации

### Этап A — безопасный контур данных

1. Внести миграцию четырёх слоёв справочника и ограничения целостности.
2. Импортировать Excel как неизменяемый источник в staging-слой.
3. Автоматически выделить записи с `30 min`, `peak`, диапазонами и отсутствием
   подтверждения, не публикуя их в расчёт.

### Этап B — утверждённый расчётный слой

1. Перенести существующие подтверждённые статические гибридные спецификации
   из кода в `draft`-спецификации.
2. Прикрепить первичные доказательства и утвердить только проверенные строки.
3. Ввести точное сопоставление к автомобилю и журнал применённой версии.

### Этап C — калькулятор

1. Принять расчётную мощность в кВт без округления.
2. Сделать отдельные таблицы для M1, EV/последовательных гибридов и
   параллельных гибридов; не смешивать их с пикапами/N1.
3. Сохранить л.с. для поиска и интерфейса, но не использовать их как основу
   юридической границы при наличии подтверждённых кВт.
4. Добавить режим безопасного отказа для неподтверждённых данных.

### Этап D — проверка и выпуск

1. Превратить HAR TKS в версионированные тестовые сценарии: входные параметры,
   ожидаемые пошлина, сбор и коэффициент утильсбора.
2. Проверить контрольные границы для EV, последовательных и параллельных
   гибридов, возрастов, объёмов и таможенного сбора.
3. Выполнить dry-run всего каталога: сколько карточек подтверждено, сколько
   требует проверки, где изменится цена.
4. Только после отчёта выполнить пересчёт и публикацию.

## Критерий завершения

Задача считается завершённой не после импорта Excel, а когда для каждой
опубликованной категории есть: нормативная версия, HAR-тесты TKS, утверждённая
спецификация с доказательством, успешный dry-run и ручная выборочная сверка
карточек.

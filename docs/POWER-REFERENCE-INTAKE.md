# Пополнение справочника мощности TL Auto

Этот справочник отделён от карточек Encar и от старых карт в коде. Данные от
заказчика, производителя или из документа сначала попадают в черновой слой и
не могут изменить публичную цену сами по себе.

## Что передавать по каждой конфигурации

Одна строка — одна однозначная версия автомобиля. Нужны следующие значения:

| Поле | Пример | Зачем |
| --- | --- | --- |
| Марка и модель | `Kia / K5` | Базовое сопоставление |
| Поколение или код модели | `DL3`, если известен | Отделяет разные поколения |
| Год или диапазон лет | `2021–2023` | Исключает версии другого года |
| Комплектация / badge | `1.6 T-GDi Signature` | Основной признак версии |
| Топливо, объём, привод | `бензин, 1598 см³, 2WD` | Исключает похожие двигатели |
| Мощность ДВС | `132 кВт` | Для бензина/дизеля |
| 30-минутная мощность ЭД | `100 кВт` | Обязательна для EV и последовательного гибрида |
| Тип гибрида | параллельный / последовательный | Определяет базу расчёта TKS |
| Источник | ссылка/файл, страница, дата | Позволяет проверить факт |

Если мощность дана в л.с., сохраняется и исходное значение, и источник. Для
расчёта мощностных границ хранится точное значение кВт без округления.

## Официальные корейские спецификации

Проверенные корейские документы хранятся в
`data/power-reference/manufacturer-korea-v1.json`. У каждой записи есть
ссылка, исходное значение производителя (например, `304 PS`), точное значение
в кВт и строго ограниченный диапазон годов/моторов/приводов. Импорт запускается
так:

```bash
# только проверить структуру и коэффициенты перевода
npm run import:manufacturer-power

# сохранить подтверждённые записи в закрытый справочник; карточки и цены не меняются
MANUFACTURER_POWER_IMPORT_DRY_RUN=false npm run import:manufacturer-power

# однозначно связать новые подтверждённые записи с карточками; цены не меняются
POWER_RESOLUTION_DRY_RUN=false npm run apply:approved-power-resolution
```

Только отдельный dry-run пересчёта показывает влияние на цены. При нём
подтверждённые кВт передаются в калькулятор напрямую, без обратной конвертации
через округлённые л.с.

## Статусы данных

1. **Черновик** — таблица, сообщение заказчика, каталог производителя или
   иной полученный материал. Он сохраняется как неизменяемая исходная строка.
2. **Проверка** — сверяем сочетание поколения, двигателя, комплектации и
   периода выпуска. Для EV и последовательных гибридов отдельно проверяем
   именно 30-минутную мощность, а не пиковую.
3. **Подтверждено** — создаётся версия спецификации и правило сопоставления.
   Только на этом этапе запись становится доступна строгому resolver.
4. **Применение** — сначала dry-run, затем ручная проверка моделей, и только
   после неё — пересчёт карточек.

## Как использовать файл от заказчика

Файл Excel можно загрузить существующей командой:

```bash
VEHICLE_POWER_WORKBOOK_FILE=/absolute/path/to/file.xlsx npm run import:vehicle-power:source
```

По умолчанию это dry-run. Для сохранения только исходных строк в закрытый
черновой слой используется `VEHICLE_POWER_IMPORT_DRY_RUN=false`. Такой импорт
не создаёт подтверждённую мощность, не пересчитывает автомобили и не меняет
цены. После проверки данные переводятся в `vehicle_power_evidence`, затем в
версионную `vehicle_power_specs`.

## Что никогда не делаем автоматически

- Не утверждаем мощность только по марке, модели или объёму двигателя.
- Не используем пиковую мощность вместо 30-минутной для EV/последовательного
  гибрида.
- Не заменяем уже опубликованную цену без dry-run и просмотра изменений.
- Не считаем сообщение без документа «официальным» фактом; оно остаётся
  черновым источником до проверки.
